Fundamento

Por que surgiu a orientação a objetos?

Paradigmas são diferentes maneiras de organizar a solução de um problema. À medida que o software cresce, a forma como o código é estruturado faz diferença.

Programação estruturada

Organização por procedimentos

O programa é dividido em funções e sequências de instruções. É uma abordagem útil, mas separar dados e operações pode dificultar a manutenção quando o sistema se torna grande.

Exemplo: funções como cadastrarCliente(), alugarEquipamento() e registrarDevolucao().
O desafio do crescimento

Muitos dados e regras

Vários clientes, equipamentos, pagamentos e locações precisam se relacionar. Alterar uma regra sem afetar outras partes exige organização.

Exemplo: impedir que um projetor indisponível seja alugado novamente.
Orientação a objetos

Dados e comportamentos juntos

A POO organiza o sistema em objetos, que carregam seu próprio estado e oferecem operações. Isso pode facilitar separação de responsabilidades, compreensão e evolução do código.

Exemplo: o objeto projetor registra sua condição e responde ao método alugar().
Ideia central: em vez de pensar apenas nas instruções, pense nas entidades do problema, nas informações que possuem e nas ações que executam. Uma abordagem não elimina a outra: Java também usa comandos estruturados dentro dos métodos.
Vocabulário da POO

Objeto, classe e instância

O objeto representa uma entidade concreta no software. A classe descreve a estrutura compartilhada por objetos do mesmo tipo.

Equipamentos reais

Uma classe pode originar muitas instâncias.

Classe não é objeto

Equipamento é o tipo geral, assim como a planta de uma casa é um modelo. projetorLED é um exemplar específico, com seus valores e estado.

O que é instanciar?

É criar um objeto a partir de sua classe. Em Java, a expressão new Equipamento(...) cria uma instância.

Estado e comportamento

Atributos e métodos

Os atributos descrevem o estado. Os métodos descrevem o que o objeto sabe fazer.

Atributos

O que um equipamento possui?

  • codigo: identificação única do item.
  • descricao: nome do produto.
  • valorDiaria: custo por dia.
  • disponivel: informa se pode ser alugado.
Exemplo de estado: Projetor LED, código EQ-101, diária de R$ 80,00, disponível = true.
Métodos

O que um equipamento faz?

  • alugar(): marca o equipamento como alugado, se estiver disponível.
  • devolver(): devolve o item ao estado disponível, se estiver alugado.
  • enviarParaManutencao(): registra uma indisponibilidade técnica.
Uma ação pode alterar o estado. Essa relação será demonstrada no laboratório.
Java • primeiros atributos e métodos
class Equipamento {
    String codigo;
    String descricao;
    double valorDiaria;
    boolean disponivel;

    void alugar() {
        if (disponivel) {
            disponivel = false;
        }
    }

    void devolver() {
        disponivel = true;
    }
}

Esse trecho mostra a estrutura de uma classe. O arquivo completo e executável está disponível no laboratório e na pasta exemplos.

Pensar antes de programar

Abstração: o que realmente importa?

Abstrair não é registrar tudo. É selecionar as características importantes para resolver o problema específico.

Importante para o sistema

Dados que precisamos considerar

  • Código e descrição do equipamento.
  • Valor da diária e disponibilidade.
  • Identificação e contato do cliente.
  • Datas de retirada e devolução.
  • Forma e situação do pagamento.
Não é necessário agora

Detalhes fora do escopo

  • Cor da roupa do cliente.
  • Música preferida do atendente.
  • Marca da caneca da recepção.
  • Previsão do tempo em outra cidade.

Um dado pode se tornar relevante se o problema mudar. A abstração depende dos requisitos.

Antes de criar campos em uma classe, pergunte: esse dado ajuda a identificar, controlar ou executar alguma operação prevista para a locadora?
